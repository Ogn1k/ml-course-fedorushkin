# Памятка для защиты (5–7 минут)

1. Задача: предсказать SalePrice, непрерывную цену. Датасет: 1460 размеченных домов,
   1459 домов без цен; test.csv используется только для итогового submission.
2. EDA: покажите examples/eda_plots.png. Правый хвост цели, корреляция качества
   и площади с ценой, смысловые пропуски бассейна/гаража, две аномальные продажи.
3. Предобработка: None при отсутствии объекта, медиана района для LotFrontage,
   медиана/мода для неизвестных значений. TotalSF, TotalBath, возраст, индикаторы.
   Качество кодируется по порядку, номинальные категории — one-hot.
4. Проверка: split 80/20, random_state=42. Статистики обучаются только внутри
   пяти фолдов; holdout не участвует в GridSearchCV. Выбросы удаляются только из train.
5. Модели: OLS без штрафа; Ridge L2; Lasso L1; ElasticNet L1+L2.
   Лучшая по CV — ElasticNet, alpha=0.001, l1_ratio=0.8.
6. Результат holdout: R²(USD)=0.9390, MAE=$14,426,
   RMSE=$21,630, RMSE(log)=0.1292. Покажите остатки и пять примеров.
7. Инференс: joblib.load полного pipeline → predict_price(исходные поля).

## Частые вопросы

- Почему log1p? Сжимает правый хвост, меняет акцент с абсолютных ошибок на относительные.
  Нормальность целевой для OLS не обязательна.
- Почему масштабирование? Штраф числовых коэффициентов должен учитывать масштаб признаков.
- Почему нет метрик на test.csv? Там нет истинных цен.
- Почему не выбрать модель с лучшим holdout? Выбор уже сделан по CV; повторный выбор
  по holdout использовал бы его для настройки.
- Почему не удалили все IQR-выбросы? Большие дорогие дома могут быть корректными объектами.
- Коэффициент — эффект ремонта? Нет, это условная ассоциация; связанные признаки
  и взаимодействия не позволяют так интерпретировать отдельный вес.
- Что улучшить? Бустинг, nested CV, Target Encoding с cross-fitting, stacking,
  интервалы прогноза, временная проверка по годам.
- Проверен ли GitHub raw? Пока проверена локальная загрузка. Сетевую проверку
  нужно выполнить после публикации; инструкция есть в README.
