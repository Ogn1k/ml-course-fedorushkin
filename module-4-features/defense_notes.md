# План защиты лабораторной №4 (5–7 минут)

1. Задача — покупка по поведению сессии. Данные UCI: 12 330 строк, 15.47% покупок.
2. Дубликаты удалены до split; seed 42; stratify; test 20%. EDA только по train.
3. Созданы 11 признаков: суммы, отношения, бинарные индикаторы, циклический месяц.
   June отображён вручную, поскольку это не стандартное трёхбуквенное сокращение.
4. RF, XGBoost, LightGBM, CatBoost обучены с весами классов. Общая предобработка —
   импутация, StandardScaler и One-Hot. Pipeline целиком обучается внутри CV.
5. По пятифолдовой CV выбрано семейство для 30 испытаний Optuna.
   Итог: Random Forest (Optuna); test ROC-AUC=0.9350, F1=0.6738.
6. Абляция показывает фактическое влияние инженерии. Удаление PageValues проверяет
   чувствительность к этому сильному полю, но не устраняет все вопросы временной доступности.
7. SHAP: summary — все сессии, waterfall — одна, dependence — связь значения и вклада.
   Для RF вклады измеряются в вероятности; base + sum(SHAP) совпадает с predict_proba.
8. Модели сохранены полными pipeline; локальная загрузка даёт те же вероятности.
   Raw-проверка подготовлена, запускать после публикации в GitHub.

## Ответы на вопросы

- Почему не только Accuracy? Константный прогноз уже даёт около 84.5%; нужны ROC/PR-AUC и F1.
- Есть ли утечка предобработки? Fit выполняется внутри обучающих фолдов Pipeline.
- Почему нет TF-IDF и геопризнаков? В обязательном наборе нет текстов и координат.
- Почему нет лагов? Нет временного порядка и полной даты сессий.
- Почему One-Hot для кодов? Код региона не задаёт числового расстояния между регионами.
- Почему не обещаем прирост? Производные могут дублировать исходные признаки; проверяем CV.
- Можно ли использовать модель в реальном времени? Сначала нужен аудит доступности
  агрегатов на момент принятия решения и проверка на будущих периодах.
